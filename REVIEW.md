# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Returns static `{"status": "ok"}` without pinging MongoDB; never raises 503 if database connection is down. | Stopping MongoDB and requesting `/health` still returns HTTP 200 instead of HTTP 503. | Added `db.command("ping")` inside a `try/except` block and raise `HTTPException(503, "Database unavailable")` on failure. |
| 2 | `compute_late_minutes` (lines 33-37) | Uses `punch_in.replace(hour=h, minute=m)` assuming `punch_in` is in local/IST time; also checks `minutes > 10` where `minutes = int((punch_in - start).total_seconds() / 60)`. If punch-in is 09:40:01 on a 09:30 shift, `diff // 60 = 10`, which is not `> 10`, returning 0 instead of 10. | A punch-in at 09:40:01 (10 min 1 sec after 09:30) returns `late_minutes = 0` instead of 10. Also UTC vs IST timezone comparison mismatch. | Converted `punch_in` to IST timezone first. Checked `(punch_in_ist - shift_start_dt).total_seconds() > 600` (strictly more than 10 minutes), and returned `int(diff_sec // 60)`. |
| 3 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round(..., 2)` which implements banker's rounding (round half to even) instead of round half-up required by rule R4. | 9.125 hours rounds to 9.12 with banker's rounding instead of 9.13. | Used Python's `decimal.Decimal` with `ROUND_HALF_UP` quantization to `0.01`. |
| 4 | `compute_overtime` (lines 44-47) | Uses `max(0, ...)` without enforcing the 30-minute minimum threshold (R3). Also uses `date_str` for shift end, which breaks for overnight shifts where shift end falls on the next calendar day. | Punching out 15 minutes after shift end returned `overtime_minutes = 15` instead of 0. Overnight shift punch-out compared against yesterday's shift end. | Added check that difference must be `>= 30` minutes, otherwise 0. For overnight shifts (`shift_end <= shift_start`), advanced shift end calendar date by +1 day. |
| 5 | `create_employee` (lines 77-85) | Application-level check-then-insert (`if db.employees.find_one(...)`) causes a race condition under concurrent requests; sets `created_at = datetime.now()` (naive local time); lacks validation for `emp_code` format and `shift_start != shift_end`. | Concurrent requests with the same `emp_code` can create duplicate employees. Also invalid inputs like `EMP_ABC` or identical shift start and end were accepted. | Created unique index on `emp_code` in MongoDB; handled `DuplicateKeyError` to return HTTP 409; used Pydantic regex validators and cross-field validation; set `created_at` in UTC epoch milliseconds. |
| 6 | `list_employees` (lines 88-96) | Bug in pagination offset: `skip = page * page_size` skips the first page entirely (e.g. page 1 skips 20 items); `total` counts the whole collection rather than the filtered subset `q`; does not sort by `emp_code` ascending. | Requesting `page=1` returned results starting from item 21; filtering by department showed the count of all employees in `total`. | Fixed skip formula to `(page - 1) * page_size`, updated count to `db.employees.count_documents(q)`, added `.sort("emp_code", 1)`. |
| 7 | `punch_in` (lines 99-121) | No check if employee exists (missing 404); uses `datetime.fromtimestamp()` producing naive datetime in system local timezone; fails to apply R1 overnight shift logic to attendance date; check-then-insert creates race condition; injects `"id"` into response; accepts any arbitrary status. | Punching in for non-existent employee crashed or inserted orphan document. Duplicate simultaneous punch-ins resulted in multiple records. Leaked `"id"` field violating OpenAPI contract. | Checked employee existence (404); computed IST date with R1 overnight shift rule; relied on MongoDB unique index on `(emp_code, date)` and caught `DuplicateKeyError` for HTTP 409; strictly validated status against `Literal["PRESENT", "WFH", "ON_DUTY"]`. |
| 8 | `list_attendance` (lines 124-150) | In-memory loading and sorting: calls `list(db.attendance_logs.find(q))` and sorts in Python memory; lacks secondary sort on `emp_code`; mutates documents by adding `"id": str(d.pop("_id"))`; lacks validation that `date_from <= date_to`. | Querying attendance on 100k records causes severe memory exhaustion and slow response times. Date range `date_from > date_to` returned 200 with empty list instead of 422. | Replaced in-memory list sorting with MongoDB index-backed cursor operations `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`, added `date_from <= date_to` check (422), and omitted `id`/`_id`. |
| 9 | Missing Startup Indexes | Starter code did not define or create any database indexes at startup, causing all queries to execute via collection scans (`COLLSCAN`). | Running `explain` on `/admin/explain/{endpoint}` showed `COLLSCAN` stages. | Added idempotent index creation in `lifespan` and module initialization for `employees` and `attendance_logs`. |
| 10 | Missing API Endpoints | Starter was missing 7 endpoints required by `openapi.yaml`: `POST /attendance/punch-out`, `PATCH /attendance/{emp_code}/{date}`, and all analytics/admin endpoints. | Client requests to these routes returned 404 Not Found. | Implemented all missing endpoints following OpenAPI schemas and rules R1-R10. |

### Things looked at and decided were NOT defects:
1. **Natural string formats for dates and times (`"YYYY-MM-DD"`, `"HH:MM"`):** While timestamps are epoch milliseconds, storing calendar dates and shift times as plain strings is by design (`DATA_MODEL.md` Section 1) to avoid forcing timezones onto abstract calendar/time values.
2. **Identification by `emp_code` rather than MongoDB `_id`:** `emp_code` is the customer's immutable business key. Hiding internal `_id` from all request and response bodies is intentional and conforms to the API contract.
3. **Pydantic v2 `model_dump()`:** Using `doc = body.model_dump()` in Pydantic v2 is the recommended approach (replacing deprecated `.dict()`).
